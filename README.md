## 🧭 How I Think

**The right tool for the job — not the loudest one.**
I'm a .NET architect by trade, but I reach for Python when the problem calls for it: automation, scraping, Telegram bots, ML integration. I don't pick technologies by hype. I pick them by fit, and I document why.

**Architecture is a business decision.**
I know Clean Architecture, DDD, and Microservices — and I know when *not* to use them. A modular monolith that ships in 3 months beats a microservices nightmare that takes 18. I choose pragmatically, own the trade-offs, and defend the choice in a design review.

**Prevention over detection.**
My goal has never been to be the hero who finds the bug at 2 AM. It's to build systems that don't need a hero. Structured logging, request tracing, defensive design, and a habit of asking *"what if this fails?"* at design time — these are how I eliminate most incidents before they happen. When one slips through, I follow the breadcrumbs I intentionally left behind.

**Security is not a feature.**
Every system I architect assumes the attacker is already inside the perimeter. Auth, authorization, input validation, and audit trails are baseline requirements — never add-ons.

### 🔧 [`dotnet-modular-monolith-starter`](https://github.com/fateh-io/dotnet-modular-monolith-starter) *(in development)*
A production-ready .NET template for teams building business systems that will grow. Each module (Sales, Inventory, Identity) is self-contained, but the whole thing runs as one deployable unit. **Ship fast now, split later — if you ever need to.**
